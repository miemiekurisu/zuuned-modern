# The README shots are published on purpose from the real library and the real player,
# and two of those facts were a leak that no rule in this file could see.  The device
# panel paints the friendly name the owner typed into the player, which on this bench is
# a person's name, in thirty of the thirty-two pictures; the photos page carried one
# real photograph; and Settings -> Library printed four watch-folder paths in plain
# text, one of them under a home folder that had already been masked by hand.  Every
# other rule here reads bytes, and a name painted into a PNG is not bytes anyone can
# grep.  So those regions are covered with a block mosaic, and the covering is checked
# rather than remembered: tests/privacy/redact_readme_screenshots.py names every region
# and proves each one is still a flat 8x8 block mosaic, run.ps1 runs it as a step, and
# a screenshot re-taken over a mask fails the gate instead of quietly un-masking it.
# What is still only checked by eye, and still true: none of the 32 shows a device
# serial or a hex GUID.  One real account name did reach the tracked tree once, as an
# artist name in three test fixtures; docs/releases/BETA_WINDOWS_2026-11-08.md records
# when that happened and what replaced it, and git grep answers zero hits for it today.
docs/readme-screenshots/|real library and player by choice; name, photograph and paths masked, mask checked
